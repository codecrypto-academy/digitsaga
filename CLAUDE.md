## 🎯 Project Overview

This project builds a **decentralized application (DApp)** for secure peer-to-peer token swaps using an Escrow smart contract on the Ethereum blockchain.

### Core Functionality
- **Token Management**: Owner authorizes which ERC20 tokens can be swapped
- **Create Operations**: User deposits Token A, requests Token B
- **Complete Operations**: Another user provides Token B, receives Token A
- **Cancel Operations**: Creator can cancel and recover their tokens
- **Debug Panel**: View balances and active operations

### Scope
- **Smart Contract**: Escrow.sol (Solidity) with full test coverage
- **Frontend**: Next.js 15 web UI with MetaMask integration
- **Deployment**: Automated scripts for Anvil/testnet
- **Testing**: Foundry unit tests + E2E workflow

### Out of Scope
- Production mainnet deployment
- Advanced features (time locks, multi-sig, governance)
- Mobile app
- Custom blockchain

## 🚀 Development Workflow

### Prerequisites
- Node.js 18+, npm or yarn
- Foundry (`forge`, `cast`, `anvil`)
- MetaMask browser extension
- Git

### Getting Started

1. **Clone/Setup Repository**
   ```bash
   git clone <repo>
   cd ESCROW
   ```

2. **Start Anvil (Local Blockchain)**
   ```bash
   anvil --host 0.0.0.0
   # Runs at 0.0.0.0:8545:8545/tcp
   ```

3. **Deploy Contracts**
   ```bash
   ./scripts/deploy.sh
   # Deploys Escrow + TokenA + TokenB
   # Generates web/.env.local with addresses
   ```

4. **Start Frontend**
   ```bash
   cd web
   npm install
   npm run dev
   # Runs at http://localhost:3000
   ```

5. **Connect MetaMask**
   - Add Anvil network (0.0.0.0:8545, chain ID 31337)
   - Import test account (private key from Anvil output)
   - Visit http://localhost:3000 and connect

6. **Test Full Workflow**
   - See `TESTING.md` for complete E2E guide

## 🔐 Security Considerations

### Smart Contract Security
- ✅ Use ReentrancyGuard to prevent reentrancy attacks
- ✅ Check access control (onlyOwner for addToken)
- ✅ Validate inputs (non-zero addresses, positive amounts)
- ✅ Use safe token transfer patterns
- ✅ Comprehensive test coverage including edge cases
- ⚠️ **No audit required for local/testnet** (only for production)

### Frontend Security
- ✅ Never store private keys locally
- ✅ Use MetaMask for all key management
- ✅ Validate user inputs before sending to contract
- ✅ Display error messages clearly
- ✅ Validate contract addresses format

### Environment Security
- ✅ Never commit `.env.local` or private keys
- ✅ Use `.env.example` as template
- ✅ Keep Anvil local-only (0.0.0.0 → localhost only)
- ✅ Rotate test accounts regularly

## 🚨 Troubleshooting

### Anvil Issues
- **Port already in use**: `lsof -i :8545` then kill process
- **Accounts not funded**: Restart Anvil and run deploy.sh again
- **Transactions not showing**: Ensure `--host 0.0.0.0` flag

### Contract Issues
- **Compilation fails**: Check OpenZeppelin imports in `remappings.txt`
- **Tests fail**: Run `forge test -vvv` for verbose output
- **Coverage low**: Add tests for untested branches

### Frontend Issues
- **MetaMask not connecting**: Ensure Anvil network added with correct chain ID (31337)
- **Contract calls fail**: Check contract address in `.env.local`
- **ABI mismatch**: Re-run deploy.sh to regenerate ABI

### Deployment Issues
- **deploy.sh fails**: Check Anvil is running with `nc -z localhost 8545`
- **Private key not working**: Use Anvil's first account private key
- **Addresses not updated**: Check `web/.env.local` was created
